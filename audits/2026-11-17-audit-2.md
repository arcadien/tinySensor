## Findings

### Finding 1
**Type:** Coherence — precision (C2)
**Requirement:** TECH-HAL-004
**Issue:** "`PORTB = 0b11111100` (PB2–PB7)": PB4–PB7 don't exist on the ATtiny84A (PB3 is RESET). The code comment in `sleep()` already says "only 4 lasts are available". The real pull-up set is PB2 and PB3. The `0b11111100` value can stay; only the text is wrong.
**Status:** fixed

### Finding 2
**Type:** Coherence — overlap (C1)
**Requirements:** TECH-HAL-004, TECH-HAL-007, PLAT-POWER-006
**Issue:** TECH-HAL-004 pulls PB2 up with no condition. With `USE_SWITCHED_5V`, PLAT-POWER-006 wants PB2 unpulled outside the sensor window, and TECH-HAL-007 says the constructor then clears `PORTB.2`. The constructor's PORTB state is split over two TECH requirements. Read alone, TECH-HAL-004 contradicts PLAT-POWER-006.
**Status:** fixed

### Finding 3
**Type:** Coherence — precision (C2), code behaviour
**Requirement:** TECH-HAL-004
**Issue:** The datasheet's BOD-disable sequence (write BODS and BODSE, then BODS within 4 cycles, then `sleep` within 3 cycles) must run right before each sleep instruction. The code (`Attiny84aHal.cpp` lines 61–64) runs it once, in the constructor, so brownout detection is not disabled during sleep by firmware. Its last line also clears BODSE in `MCUSR` instead of `MCUCR`. This needs either a code change through `/rbd` (move the sequence into `sleep()`), or a requirement text that admits the BOD state comes from the fuses.
**Status:** fixed

### Finding 4
**Type:** Coherence — precision (C2)
**Requirements:** PLAT-POWER-007, TECH-HAL-004
**Issue:** PLAT-POWER-007 is checked against the v3.0 schematic only, and doesn't say which boards and environments it covers (S_02–S_05, robot, devmodule, mushroom, v2.2 rework). Since TECH-HAL-004 (`PORTA = 0`) applies to every build, a board without R2/R3 loses its I2C pull-ups. The bench check on such a board is still pending.
**Status:** fixed

### Finding 5
**Type:** Coherence — precision (C2)
**Requirements:** PLAT-POWER-003, TECH-HAL-004
**Issue:** "Every other pin is an input, with pull-ups on the unused ones" doesn't list the pins. Since TECH-HAL-004 now says PORTA has no unused pin, the sleep state of PA0, PA1, PA7, PB1, PB2 and PB3 is open to reading. The code pulls up PB3 (and PB2, unless `USE_SWITCHED_5V` is set) and keeps PA7's last output level as its PORTA bit.
**Status:** fixed

### Finding 6
**Type:** Coherence — precision (C2)
**Requirement:** TECH-HAL-002
**Issue:** The token list gives `S`=`SerialGoHigh` and `W`=`SerialGoLow`, but the method is `SerialWriteBit(level)` (`S` high, `W` low, TECH-SERIAL-001). The `I` token (`Init`, TECH-HAL-006, asserted in `test_main_cycle`) is missing.
**Status:** fixed

### Finding 7
